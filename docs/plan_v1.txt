2. THE CORE DATA CHALLENGE — read this before building anything
---------------------------------------------------------
The label we actually want (per planB.txt Section 3, Step 4) is:

  Dropout % = 1 - (learners who reached matric-writing stage /
                    learners who started Grade 10 that year)

Calculating this REQUIRES per-grade, per-year enrollment counts
per school (e.g., "how many kids were in Grade 10 at School X in
2021, and how many of School X's kids were in Grade 12 in 2023").

None of the datasets we currently have in hand (Section 1a-f)
contain grade-level enrollment breakdowns. The two candidates
that MIGHT have this are:
  - The No Fee Schools PDFs (c) — IF their "learner numbers" are
    broken down by grade, not just a school total. Unverified.
  - The SNAP Survey (g) — the most likely real source for this,
    but it's gated behind DataFirst registration, so we can't
    confirm grade-level granularity until someone on the team
    registers and opens it.

This is the single most important open question for the whole
project. Resolve it FIRST (Section 5, Step 0) before committing
engineering time to a full regression pipeline.

Because of this, this plan runs TWO TRACKS in parallel:

  TRACK A — Full pipeline (the real, validated regression from
  planB.txt Section 4), built once true cohort-level enrollment
  data is confirmed and obtained.

  TRACK B — Hackathon MVP (buildable THIS weekend, from data
  already in hand), an explainable risk-ranking score rather
  than a fully-validated regression, clearly presented as a
  prototype with a stated roadmap to Track A.

Judges respect "here's what we built with real data, here's
exactly what's missing and how we'd close the gap" far more than
a model quietly trained on a fabricated label. Say this in the
presentation.


3. TRACK B — HACKATHON MVP (build this first, it's demoable)
---------------------------------------------------------
Goal: a defensible, explainable per-school Dropout Risk Score
(0-100) for the 475 WC secondary/intermediate/combined schools,
ranked into a dashboard — without pretending we have a validated
regression we don't have the label data for yet.

3.1 Feature set (from data already in hand)
  - quintile_score        <- QUINTILES mapped NQ1=1 ... NQ5=5
                             (lower quintile = less funded =
                             historically higher risk)
  - no_fee_flag           <- NOFEESCHOOL (Y/N -> 1/0)
  - district              <- EDUCATIONDISTRICT (categorical)
  - school_phase          <- SCHOOLTYPE (Secondary/Intermediate/
                             Combined)
  - pass_rate_2024        <- from NSC_School_Performance_Report
                             (once extracted)
  - pass_rate_trend       <- slope/delta across the 3-year history
                             embedded in the same NSC report
  - remoteness_proxy      <- engineered from LATITUDE/LONGITUDE:
                             distance to Cape Town CBD (or nearest
                             major town centroid) as a rural/
                             urban stand-in, since no explicit
                             rural/urban column exists in our data
  - district_area_sqkm    <- from SA_Education_District_Boundaries,
                             joined on district name (larger area
                             + same school count roughly implies
                             more rural/dispersed)
  - enrollment_delta      <- ONLY if the No Fee Schools PDFs turn
                             out to have per-grade or per-school
                             total learner counts for both 2023
                             and 2025 (2-point trend, noisy, but
                             usable as a directional signal)

3.2 How the score is built (be explicit about this to judges)
  This is a transparent WEIGHTED INDEX, not a black-box trained
  model, because we do not yet have verified ground-truth dropout
  % per school to train a regression against. Formula sketch:

    risk_score = w1*(6 - quintile_score)/5        [lower quintile = higher risk]
               + w2*no_fee_flag
               + w3*normalize(-pass_rate_trend)    [declining pass rate = higher risk]
               + w4*normalize(remoteness_proxy)
               + w5*normalize(district_area_sqkm)

  Weights (w1..w5) start from research-informed defaults (e.g.
  quintile and pass-rate trend weighted highest, since those are
  the two factors most consistently cited in the Zero Dropout
  Campaign's own published material) and are documented plainly
  in the dashboard/deck so judges can see exactly how a school's
  score was built — this is a FEATURE, not a limitation: it's
  more auditable than an opaque model would be at this stage.

3.3 Calibration sanity-check (do this, it's cheap and credible)
  Before presenting, check: does the AVERAGE risk score across
  all 475 schools roughly track the known national benchmark
  (~16% Gr10->11 loss, ~22% Gr11->12 loss, DG Murray Trust)? If
  our average school lands wildly outside that range, the weights
  need adjusting. This isn't validation, but it's an honest gut-
  check that judges will ask about.

3.4 Output
  - Grist table: EMIS, Name, District, Quintile, Pass-rate trend,
    Risk Score, Rank
  - Flourish: ranked bar chart (top 20 highest-risk schools) +
    a simple map (using LATITUDE/LONGITUDE) colored by risk score
  - One-line takeaway per top school: "School X flagged mainly
    due to [lowest quintile / declining pass rate / distance]"
    — feature-level transparency, which is the same spirit as the
    "feature importance" step in the full model (Track A, Step 7)
    but achievable without a trained model.


4. TRACK A — FULL PIPELINE (target architecture, build once data allows)
---------------------------------------------------------
This is the pipeline from planB.txt Section 4, unchanged in
approach, restated here against our real files:

  STEP 1 - Collect (mostly done)
    Western Cape schools identity/quintile: DONE (Section 1a).
    No Fee Schools 2023/2025: DONE, needs extraction (Section 1c).
    NSC pass rates 2024 (+3yr history): DONE, needs extraction
    (Section 1d).
    SNAP survey (educator counts, possible grade-level learner
    counts): PENDING DataFirst registration (Section 1g).
    National EMIS masterlist: PENDING DataFirst registration, not
    required for a WC-only pilot (Section 1a already covers WC).

  STEP 2 - Clean and join
    Join key: EMIS number.
    Join WesternCape_Public_Ordinary_Schools_2025.csv (identity,
    quintile) + extracted No Fee Schools table (learner counts by
    year) + extracted NSC table (pass rate by year) + SNAP (staff
    counts, once obtained) into one row-per-school-per-year table.
    Known join risks: EMIS formatting (leading zeros — EMIS is a
    text/string field, e.g. "0100000217", not numeric — make sure
    no tool silently converts it to a number and drops the
    leading zero), schools present in one source but not another,
    district name spelling differences between sources.

  STEP 3 - Engineer features
    Same as Track B's feature set (Section 3.1), PLUS once SNAP
    is available:
      - teacher_learner_ratio <- educators / learners, by year
      - true grade-level enrollment deltas (Gr9->10, Gr10->11,
        Gr11->12), IF SNAP confirms grade-level granularity

  STEP 4 - Build the true label
    For a school's Grade 10 cohort in year Y, track that same
    school's enrollment through Grade 11 (Y+1) and Grade 12 (Y+2),
    and matric candidates (Y+2 or later, allowing repeaters).
    Dropout % (label) = 1 - (learners who reached matric-writing
    stage / learners who started Grade 10 that year), for each
    historical cohort where we already know the outcome.
    This step is BLOCKED until Section 2's open question is
    resolved.

  STEP 5 - Split the data
    Train on older cohorts (e.g. Grade 10 classes 2016-2020,
    outcomes already known) and hold back the most recent known
    cohort (e.g. 2021/2022) purely for testing.

  STEP 6 - Train the model
    Start simple: Linear Regression (explainable: "each feature
    adds/subtracts some % risk").
    Then try Random Forest Regressor or Gradient Boosting
    (XGBoost) — captures interactions (e.g. very underfunded AND
    very short-staffed together may compound risk beyond either
    alone).
    Compare both — if the stronger model isn't meaningfully
    better, keep the simpler, more explainable one.

  STEP 7 - Evaluate
    MAE (mean absolute error, in percentage points).
    R² (how much variance between high-risk and low-risk schools
    the model explains).
    Feature importance — explain WHY a school is flagged, not
    just THAT it's flagged.

  STEP 8 - Deploy / present
    Grist: live, shareable school-level table (school, district,
    % predicted, key driving factor).
    Flourish: ranked bar chart / choropleth map by predicted risk.
